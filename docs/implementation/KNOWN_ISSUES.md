# Known Issues

The 2026-08-07 phase-order recovery has no known Phase 2/3 source-level blocker after the fresh
full-workspace formatting, lint, strict TypeScript, unit, integration, migration and normal
production-build gates. The Cloudflare-specific bundle remains unproduced because OpenNext cannot
create its generated symlink on this Windows host. Exact evidence is in `PHASE_STATUS.md`.
External/documentary items remain below and must not be represented as locally verified.

## Resolved during the Phase 1 audit and Google amendment

| Issue                                                                                                  | Resolution                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Internal 5xx `HttpException` messages were not forcibly sanitized (open Phase 1 prerequisite)          | Generic 5xx becomes `INTERNAL_ERROR`; 503 becomes a sanitized `PROVIDER_UNAVAILABLE`. Both discard original messages/details and are covered by filter/e2e tests                             |
| `@gdm/mobile` unit tests and the Android export build failed (`Cannot find module '@babel/traverse'`)  | Root `@babel/traverse` devDependency plus workspace-wide React 19.2.8 alignment; 12 suites / 46 tests and `expo export` now pass. See ADR-0013                                               |
| The login response omitted `status`, breaking the shared contract and the `@gdm/api` type-check        | `status: 'AUTHENTICATED'` is now emitted and typed end to end. See ADR-0014                                                                                                                  |
| 17 ESLint errors and 14 mobile TypeScript errors in Phase 1 code                                       | Dead `sessionSummaryFor` removed, non-null assertions replaced with bounds-safe `Buffer` reads and explicit checks, return types added, and the mobile `AuthenticationGrant` union narrowed  |
| The migration integration test asserted a stale applied-migration count                                | The expectation is now derived from `migrations/meta/_journal.json`                                                                                                                          |
| Google ID-token/JWKS errors could be misclassified or under-validated                                  | Verification now has dedicated issuer/audience/expiry/nonce/verified-email/subject/`azp` tests; unknown keys are invalid tokens while provider transport failure is retryable                |
| Google invitation/link/unlink behavior lacked real-store assurance                                     | Migrated-PGlite tests prove invitation activation audits without membership creation, provider/subject uniqueness, successful unlink/session revocation/audit, and final-method rejection    |
| Linux CI could fail before OpenNext because production builds require public Google client identifiers | The workflow now provides explicit non-production public Web/iOS identifiers and has a repository regression test covering Linux, OpenNext, Docker and the absence of a Google client secret |
| OpenAPI advertised a hard-coded refresh cookie name                                                    | Swagger now uses validated `AUTH_REFRESH_COOKIE_NAME`; the API application e2e test changes the configured name and verifies the generated security scheme                                   |
